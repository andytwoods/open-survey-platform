## 2026-10-17 – F5: residual results-layouts drag flake (branch agent/47)

- Root cause: not the drag protocol. bits-ui's body scroll lock sets `pointer-events: none` on `<body>` while a dialog is open and clears it on a `setTimeout(…, 24)` after the dialog unmounts. `dragCardOnto` pressed the mouse as soon as the "Unsaved changes" indicator hid, which is the same flush that closes the Save as… dialog, so the press raced that timer: `<body>` was still `none` right after the close in 6/6 samples; when a starved renderer timer (a loaded machine) leaves it so until after `mouse.down`, the press hits `<html>`, Blink finds nothing draggable at the press point, `dragstart` never fires and the drop state never shows. - Fix (test only): `handle.hover()` before centring and pressing. Playwright's "receives events" check waits until the handle really gets the pointer, retrying while bits-ui's lock still blocks it; the centring comes after it because those retries re-scroll. No retries, no timer waits.
