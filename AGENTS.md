# AGENTS.md: guide for AI agents and contributors

Open Survey Platform: an MIT-licensed, GUI-first survey builder for academic research. Surveys are authored in our own JSON model (`osp-survey`), run in **our own browser runtime** (`web/runtime` + the TypeScript engine `web/engine`; design in `planning/runtime-design.md`), and can be exported to other platforms (XLSForm/Enketo, LimeSurvey, SurveyJS, QSF). The server only saves data and counts across participants. Structure modelled on PhotoCraft's `AGENTS.md` (`planning/review.md` §3.3).

## 2. Repo map and layers

```text
pyproject.toml   uv workspace root (members: python/*), import-linter + ruff + pytest config
python/          uv workspace members, layers enforced by import-linter (`uv run lint-imports`)
  L0  osp-expr                          no workspace deps (future: osp-fmt-xlsform, osp-fmt-lss …)
  L1  osp-spec
  L2  osp-engine, osp-ops
  L3  osp-targets, osp-qa
  L4  osp-runtime, osp-store            I/O allowed from here up (future: osp-limesurvey)
  L5  osp-app
  L6  osp-api, osp-cli, osp-mcp         thin shells; only L6 may import the web framework
web/             pnpm workspace, boundaries enforced by dependency-cruiser (.dependency-cruiser.cjs)
  builder        Vite multi-page build, one entry per page (may import api-client, ui-components)
  api-client     generated from contract/openapi.json (imports no workspace package)
  ui-components  shared Svelte components (must not import api-client); nothing imports builder
  tooling/       workspace-level tests (e.g. boundary rules)
contract/        openapi.json (generated by `make contract`, committed)
fixtures/        survey + answer script + expected trace, shared by every test layer
scripts/         licence_check.py, contract.py (OpenAPI dump + TS client), stop-hook.sh
tests/           repo-level tests (layers, licences, contract, stop hook)
spikes/          throwaway code: never imported, never in a workspace or a check
log/devlog.md    what landed, numbers, what's open
```

A package imports only **lower** layers; packages in the same layer don't import each other. L0–L3 do no I/O: no network, database, clock or global randomness (import-linter forbids `socket`, `http`, `urllib`, `sqlite3`, `random`, `subprocess`, `asyncio` … there). A new package must be added to the layers contract in `/pyproject.toml` (`tests/test_layers.py` fails otherwise) and to the root `dev` dependency group + `[tool.uv.sources]`.

## 3. Golden rules

1. **Semantics come from `planning/semantics.md`.** If a case isn't covered, add it under "Open questions" and stop work on that part. Never invent behaviour.
2. **Every survey edit is an op** in `osp-ops`: id, params schema, `enabled`, `run → (survey', inverse)`, tests, and a hostile-input fuzz case. App actions (deploy, auth) are app commands in `osp-app`, in the same registry, but not survey ops.
3. **Never crash on input.** Bad surveys, params, files or API responses produce a diagnostic, not an unhandled exception.
4. **Clean-room.** Enketo/pyxform are dependencies, never copied in. Never copy code from LimeSurvey (GPL), Qualtrics, SurveyJS Creator, KoboToolbox, Formbricks or any non-permissive project, and don't paste their source into prompts. Learn from docs and observed behaviour.
5. **Permissive dependencies only** (`licence-policy.toml`, checked by `make licence-check` for Python and JS):
   - Allowed: MIT, MIT-0, BSD-2-Clause, BSD-3-Clause, ISC, Apache-2.0, CC0-1.0, 0BSD, Python-2.0/PSF-2.0, Unlicense, BlueOak-1.0.0, Beerware/WTFPL-style, CC-BY-4.0, Zlib, BSL-1.0 (Boost).
   - Runtime exceptions (named, human-approved): `certifi` (MPL-2.0, unmodified).
   - Dual licences pass when one option is permissive; we take that option.
   - MPL-2.0 is allowed for **dev/test/build-only** dependencies, never at runtime.
   - Denied: GPL, AGPL, LGPL, BUSL (Business Source; not BSL-1.0 Boost), SSPL, Commons Clause, and anything unknown.
   - Unidentifiable metadata gets an `[[override]]` with a reason. A copyleft or unclear licence is a "Needs human" item: pick an alternative, never override it.
6. **Completeness guard.** A new `osp-spec` field must be handled by the serialiser and listed in every target's capability table, or CI fails.
7. **No real personal data** in fixtures, logs, screenshots or prompts.
8. **The UI is thin.** No survey logic in Svelte. It calls ops through the generated API client.

## 4. Definition of done

Set up with `make install` (`uv sync` + `pnpm -C web install`). Run `make check` before finishing. It runs:

```sh
uv run pytest                     # Python unit + fixture tests (incl. layer/licence/contract/hook proofs)
uv run lint-imports               # Python layers
uv run ruff check . && uv run ruff format --check .
pnpm -C web check                 # svelte-check, eslint, dependency-cruiser
pnpm -C web test                  # vitest
vite build (builder)              # page entries + manifest.json in web/builder/build
make contract-check               # OpenAPI + TS client regenerated in memory; fail if stale
make licence-check                # Python + JS licences vs licence-policy.toml
make harness-quick                # Enketo equivalence (Playwright) on touched fixtures (stub for now)
```

Changed an endpoint? Run `make contract` and commit `contract/openapi.json` and `web/api-client/src/schema.d.ts`.

A Claude Code **Stop hook** (`.claude/settings.json` → `scripts/stop-hook.sh`) runs `make check` when you try to finish with uncommitted changes or new commits, and blocks with the failing output. After 3 consecutive blocks it lets the session end: then mark the task `blocked`.

A task is done when `make check` is green **and** the task's acceptance criteria in `planning/tasks.md` are met with tests. Then append a 3–5 line entry to `log/devlog.md` (what landed, numbers, what's still open) and mark the task `review`.

## 5. Parallel agents

- **One agent, one task, one git worktree, one branch** (`agent/<task-id>`). Never work on `main`.
- Edit only the files your task owns. Shared registries (op list, router, layer config) get small, surgical additions. Re-read before editing.
- New ops go in a **new module** (`osp_ops/<area>_ops.py`) rather than growing a shared file.
- If another agent's change breaks the build on `main`, don't fix their files. Note it in the devlog and wait or pick another task.
- Commit small and often. Sessions can end abruptly, and the devlog plus a green branch is how the next agent picks up.

## 6. When to stop and ask a human

- A product or research-design decision (anything not in `semantics.md` or `review.md`).
- A dependency with a non-permissive or unclear licence.
- Anything touching auth, credentials, participant data handling or the deploy-to-LimeSurvey path for real instances.
- Three failed attempts at the same failing test. Write down what you tried.

Write the question in the task's "Needs human" field and move on to another task.
